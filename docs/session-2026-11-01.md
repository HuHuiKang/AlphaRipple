# 2026-11-01 会话总结：MinerU 选型、环境搭建与解析评估

当前进度和下一步写在 [progress.md](progress.md) 里。本文记录这次会话做了什么、为什么这样做、得到了什么结论。

## 1. 选型：Data-Juicer 适不适合本项目

**问题**：想把研报等资料下载下来，再解析成规整的数据集。Data-Juicer 能不能承担这件事？

**结论**：只能承担一部分，不适合当主干。

- Data-Juicer 是为大模型训练准备数据的工具。它的输入是已经变成文本的语料（jsonl 或 parquet），用 YAML 把上百个算子串成流水线，支持 Ray 分布式运行。
- 它在本项目里做不了这些事：
  - 下载：没有采集功能
  - PDF 解析：只能做基础的转文本，处理不了多栏版面、跨页表格和扫描件
  - 实体对齐：没有这项功能
  - 关系抽取：有通用的抽取算子，但输出格式不符合本项目的关系 schema，也没有证据校验
- 它在本项目里能用上的地方：
  - 处理层：去重（MinHash/SimHash）、质量过滤、清洗
  - 闭环层：构造 SFT/DPO 数据、做数据配比

**定下来的链路**：

```
采集（巨潮资讯 + AKShare/Tushare）→ Bronze 存原始 PDF
→ MinerU 解析 → Silver 存 JSON/Markdown（带页码）
→ Data-Juicer 清洗（以后再加）
→ LLM 按自定义 schema 抽取，每条关系带证据原文和页码
→ 实体对齐 + 校验 → Gold
```

**注意**：券商研报一般有版权，只能自己做研究用，不要提交到公开仓库或对外分发。巨潮资讯上的公告是公开披露信息，这方面风险小得多。

## 2. 环境方案

**问题**：用 venv、conda 还是其他工具管理环境？

**结论**：

| 环境 | 工具 | 理由 |
|---|---|---|
| 主项目 AlphaRipple | uv | 自动生成 `uv.lock`，环境可以复现；能自己管理 Python 版本；安装快；可以在配置里写死 GPU 版 torch 的下载源 |
| MinerU | 单独的 uv venv | MinerU 的依赖锁得很死（比如 `transformers>=5.10`、`torch>=2.7`），和以后的 Dagster、Ray、PyG 混装迟早会冲突。MinerU 本身可以通过命令行或 HTTP 服务调用，主项目不需要 import 它 |
| Qlib | 保留原来的 conda 环境 `qlib_env` | Qlib 在 Windows 上用 conda 装更省事 |

conda 的主要优势是能装 CUDA toolkit 这类非 Python 的二进制库。但 PyPI 上的 torch wheel 已经自带 CUDA 运行时，所以本项目用不到这个优势。

`D:\Syncthing\projects` 已经取消了 Syncthing 同步，所以 `.venv` 放在项目目录里没有问题。

## 3. 安装 MinerU

### 3.1 发现 MinerU 并没有装上

`D:\Syncthing\projects\obs_practice\MinerU` 是用 `git clone` 下载的源码。查了 conda 的 base 和 qlib_env 两个环境，里面都没有 mineru，也没有 torch。clone 只是把源码下载下来，要装进某个 Python 环境，才会有 `mineru` 命令。

### 3.2 纠正：这份源码是 MinerU 4.x，不是 2.x

一开始我按 2.x 的写法给了命令，后来看了 pyproject.toml 和 README 才发现写错了。4.x 的写法如下：

| 项目 | 2.x（网上教程多是这种） | 4.x（本机用的） |
|---|---|---|
| 安装可选依赖 | `mineru[core]` | `mineru[torch]` 或 `mineru[full]` |
| 选择解析质量 | `-b pipeline` 或 `-b vlm` | `--tier basic/standard/advanced` |
| 解析命令 | `mineru -p x.pdf -o out` | `mineru-kit parse x.pdf -o out` |
| 运行方式 | 直接运行 | 两种：`mineru-kit` 在当前进程里直接解析；`mineru` 经过后台服务 |

README 对硬件的建议：NVIDIA 显卡有 4GB 以上显存，用 `basic` 档加 `[torch]`；有 8GB 以上显存，用 `standard` 档加 `[full]`。本机是 RTX 4060 Laptop，8GB 显存还要分一部分给显示，所以选了 `[torch]`。

### 3.3 安装步骤

```powershell
cd D:\Syncthing\projects\obs_practice\MinerU
uv venv .venv --python 3.12
.venv\Scripts\Activate.ps1
uv pip install torch torchvision --index-url https://download.pytorch.org/whl/cu126   # 必须先装
uv pip install "mineru[torch]>=4.0,<5"
mineru-models-download --tier basic --small-backend torch --source modelscope
mineru-models-download --tier standard --source modelscope
```

- **为什么要先装 torch**：Windows 上直接装 mineru，pip 会顺带装一个 CPU 版的 torch。先装好 GPU 版，后面装 mineru 时版本要求已经满足，就会保留 GPU 版。
- **为什么选 cu126**：显卡驱动是 566.26，支持 CUDA 12.x，cu126 比较稳。
- **为什么用 3.12**：base 环境的 3.13 太新，torch、paddle、PyG 这类库可能还不支持。

### 3.4 验证结果

| 检查项 | 结果 |
|---|---|
| `where.exe mineru` | 指向 `MinerU\.venv\Scripts\mineru.exe` ✅ |
| `mineru version --json` | 4.1.3，Python 3.12.16 ✅ |
| torch | `2.14.1+cu126`，`cuda.is_available()` 为 `True` ✅ |
| `mineru-kit models show` | 小模型后端 torch，VLM 引擎 llama-cpp ✅ |

- **模型位置**：`C:\Users\hk929\.mineru\models`，包括 `MinerU-4_models_torch` 和 `MinerU2.5-Pro-2605-1.2B-GGUF`。
- **VLM 怎么用 GPU**：VLM 由 llama.cpp 运行，在 Windows 上通过 Vulkan 调用 GPU（安装包里带了 `ggml-vulkan.dll`），不走 CUDA。
- **表格模型跑在 CPU 上**：表格识别用的 ONNX 模型，日志显示 `CPUExecutionProvider`，没有用 GPU。

### 3.5 本地解析和远程解析

`mineru server status --json` 里有两项：

- `parse_server.local.mode` 是 `disabled`：本地解析服务没有启用。
- `remote` 可用，指向 `https://mineru.net/api`：可以用官方云端解析，但文件会被上传出去。

查源码确认：`mineru-kit parse` 默认在当前进程里加载模型解析，**只有加了 `--remote` 才会把文件传到云端**（见 `MinerU/kit/commands/parse.py` 第 84 行）。所以现在用 `mineru-kit` 不需要启动 server。

以后如果要用经过 server 的方式（有文档库、缓存和定位符），这样启用本地解析：

```powershell
mineru config set parse_server.local.mode managed
mineru config set parse_server.local.managed_tier basic
mineru server restart
```

## 4. 搭建主项目的 uv 环境

```powershell
cd D:\Syncthing\projects\obs_practice\AlphaRipple
uv init
# 把 pyproject.toml 里的 requires-python 改成 ">=3.12"
uv python pin 3.12
uv sync
uv run python --version   # 输出 Python 3.12.16
```

过程中遇到的问题：

| 现象 | 原因 | 解决 |
|---|---|---|
| `uv add` 报缺少参数 | `uv add` 后面必须跟包名，比如 `uv add pydantic` | 现在还用不到依赖，先不加 |
| `uv init` 生成的是 3.13 | 它用了 conda base 环境里的 3.13 | 改成 3.12 |
| `uv python pin 3.12` 被拒绝 | pyproject.toml 里写的是 `requires-python >=3.13`，3.12 不满足 | 先改 pyproject.toml，再 pin |
| hardlink 警告 | uv 缓存在 C 盘，项目在 D 盘，硬链接不能跨盘，uv 退回到完整复制 | 不影响使用。想消除警告，就设置 `UV_CACHE_DIR=D:\uv-cache` 把缓存移到 D 盘 |
| 在 PowerShell 里用 `source` 报错 | `source` 是 bash 的命令 | 改用 `.venv\Scripts\Activate.ps1`。用 uv 时其实不需要激活，直接 `uv run` 就行 |
| 提示符同时显示 `(base)` 和 `(.venv)` | conda base 和 venv 同时激活了 | 不影响使用。在 AlphaRipple 里干活前先 `deactivate`，可以避免搞混 |

- uv 是装在 conda base 里的（`D:\APP\MiniConda\Scripts\uv.exe`），所以 `(base)` 激活时才能用 `uv` 命令。
- 提示符里显示的 `(alpharipple)` 就是项目的 `.venv`，这个名字取自 `.venv\pyvenv.cfg` 里的 `prompt` 字段。

## 5. MinerU 的输出格式

`-f middle_json` 输出的 JSON，格式名叫 `docvortex.middle 2.0`，结构如下：

```
{ metadata, extensions, pages[], is_full_document, schema, schema_version }
pages[]  → { page_idx (从 0 开始), blocks[] }
blocks[] → { type, index, bbox (0~1 归一化坐标), content }
```

- `type` 的取值有：`text`、`paragraph_title`、`doc_title`、`table`、`chart`、`image`、`list`、`header`、`footer`、`page_number`、`index`。
- 表格块：`content` 里有 `table_caption`，还有 `table_body`（内容是 HTML）。
- 图表块：`content` 里有 `chart_caption`、`chart_body`、`chart_footnote`。
- `extensions.mineru` 记录了用的档位，以及 `parse_mode`。`parse_mode` 为 `txt` 表示直接读取 PDF 的文字层，为 `ocr` 表示做了文字识别。

`-f markdown` 输出的 md 适合人看，但**里面没有页码**，程序处理要用 JSON。basic 档的 md 里还嵌入了 base64 编码的图片，文件会比较大。

## 6. 三档评估（华金证券研报第 1–5 页）

### 6.1 档位背后的实际区别

查源码 `MinerU/parser/tier.py` 和 `backend/analysis/pdf/window.py`，三个档位的区别如下：

| 档位 | 内部处理强度 | 用到的模型 | 图表分析 |
|---|---|---|---|
| basic | medium | 只用小模型（版面、OCR、表格） | 否 |
| standard | high | 小模型 + 1.2B VLM，VLM 用来改进版面和内容识别 | 否 |
| advanced | xhigh | 和 standard 用同一套模型，推理计算更多 | **是**（只有这一档开启 `image_analysis`） |

### 6.2 实测结果

| 档位 | 5 页耗时 | 峰值 | 图表数据 | 第 1 页侧边栏小表格 | 第 2 页财务表 |
|---|---|---|---|---|---|
| basic | 6.3s（0.8 页/秒） | 未记录 | 空 | 数值挤进了标签那一列，"价格区间"识别成 `1` | 正确 |
| standard | 9.1s（0.55 页/秒） | 76% | 空 | **识别成两列表格，值都对** | 正确 |
| advanced | 17.1s（0.29 页/秒） | 100% | **4 张图全部转成表格** | 没识别成表格，拆成了逐行文字 | 正确 |

峰值是 `nvidia-smi` 上看到的数字，当时没有分清是显存还是 GPU 利用率。如果是显存，advanced 已经到顶，以后图表多、页数多时可能会显存溢出（OOM）。

### 6.3 图表数据的准确度

advanced 提取的"图 1 公司收入规模"：

```
| 2023年 | ~100 | 2024年 | ~250 | 2025年 | ~630 |   ← 单位：亿元
```

第 2 页表格里的精确值是 2025 年营收 61,799.3 百万元，也就是 618 亿；模型从柱状图估出来的是 `~630`。数值前的 `~` 是模型自己标的，表示估算。不过，图 3 的毛利率（`41.0`、`79.2`）和图 4 的 ROE（`30.30`）没有 `~`，应该是直接读了图上标注的数字，准确度高得多。

**对后面设计的影响**：
- schema 里每条数据都要记录来源类型：表格、正文还是图表估算。
- 图表估算的值只能当辅助证据，不能用来计算传导系数。
- 同一个数据如果表格里也有，优先用表格的值。

### 6.4 人工核对的结论

- 用 basic 的 md 对照原 PDF：内容基本对得上；少数段落因为换页被断开，需要手动接上。

## 9. 踩过的坑

- **MinerU 的版本**：网上的教程大多是 2.x 的写法，4.x 的命令和参数都变了。遇到问题，以本机源码和 `--help` 的输出为准。
- **torch 的安装顺序**：先装 GPU 版 torch，再装 mineru。顺序反了会装上 CPU 版。
- **PowerShell 和 bash 的区别**：
  - 激活环境不能用 `source`，要用 `.venv\Scripts\Activate.ps1`
  - 查命令位置要写 `where.exe`，单写 `where` 会被当成 PowerShell 的 `Where-Object`
  - 如果报"禁止运行脚本"，先执行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`
- **路径**：文件名里有中文和全角冒号"："，路径要加引号，或者按 Tab 键自动补全。
- **输出目录**：每个档位、每份文档输出到单独的目录，避免互相覆盖。
- **md 里没有页码**：后面要做证据定位，必须用 JSON。
- **jieba 的 SyntaxWarning**：这是旧库在新版 Python 上产生的警告，可以忽略。
